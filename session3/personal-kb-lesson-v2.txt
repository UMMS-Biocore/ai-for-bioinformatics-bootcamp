CLASS DAY:

Build a personal, AI-powered knowledge base on atopic dermatitis using Claude Code or Codex CLI. Based on Andrej Karpathy’s LLM Wiki design, the knowledge base combines immutable raw source storage with an AI-maintained linked wiki that distills and organizes what those sources contain. You’ll learn how to ingest research, search scientific literature with Paperclip, track research tasks, delegate work to agents, visualize the resulting knowledge graph, and use the knowledge base as a persistent research system that AI agents can query on your behalf in response to your questions.

1. Open Terminal 
Mac: Cmd + Spacebar Terminal
Windows: Win + R → type cmd → Enter

2. Make new folder for your knowledge base
Mac or Windows: 
mkdir my-kb-atopic-dermatitis
cd my-kb-atopic-dermatitis

3. Start Claude Code or Codex CLI
claude
codex

**What did you observe?**
- How is interacting with the agent here different from using Claude or ChatGPT in a browser?

4. Create kb
> Turn this folder into my personal knowledge base about atopic dermatitis. Here's how it works:

> - I collect sources (articles, papers, notes) in raw/. You never change them.
> - You read them and write a wiki in wiki/: one page per idea, person, or thing, linked with [[page-name]], and every fact cites the raw/ file it came from. Keep wiki/index.md as a list of every page and wiki/log.md as a history of changes.
> - When I say "ingest", find all files in raw/ that no wiki page cites yet, read closely and choose 3-5 key takeaways from each, turn them into wiki pages, and list the pages you created or changed. If existing wiki pages exist, check the wiki/index.md page to a) ensure you're not ingesting duplicate data; b) see if existing page exists for which you can add the new data; c) note any inconsistencies or contradictions within the wiki. Note that every wiki page must include a created-on date and last-updated date.
> - When I ask a question, read the wiki/index.md to see which pages are likely to contain relevant information, then answer from the wiki with citations. If the wiki lacks information you think would be needed, alert the user and ask if they'd like you to do a web search. At any point during a user session, if interesting insights arise, offer to save them back to the wiki.

> Write these rules into AGENTS.md so every future session follows them, set everything up, and tell me in five bullets what you built.

**What did you observe?**
- What files and folders did the agent create?
- What is the difference between the `raw/` documents and the `wiki/`?

Paperclip gives your agent direct CLI access to 8M+ papers—standard search and retrieval functions, plus several powerful tools that, when used together, let agents actually explore, deep-dive, and synthesize. You can sign up for a free account and install the cli and skill for your agents to use

7. Add a research tracker
> Add a research task tracker to this knowledge base.

> The tracker: keep tasks in research_tasks/tasks.jsonl at this knowledge base's root (a sibling of raw/ and wiki/, not inside either), one task per line, with id, question, priority (high, medium, low), status (to do, in progress, done), created and updated dates, notes, and the path to the findings once done. I may edit this file by hand, so never drop fields you don't recognize.

**What did you observe?**
- Where did the agent store the research tracker?
- Open the file in a plain text editor, what information does each research task contain?

9b. Build a viewer while the research is running
> Write a small script that reads every page in wiki/ and generates
  wiki-map.html: a 3-D interactive force-directed graph with one node per page
  and one edge per [[link]]. Support standard graph exploration and controls,
  e.g. moving, zooming, rotating, back and forward buttons similar to browser history controls 
  re-navigating between selected nodes (each click centers the previous/next selected node on the screen and 
  shows the page in the sidebar), etc. Include a search bar. Node labels should fade in
  and out based on zoom.  Size nodes by
  number of links, color them by page type, and show each page's summary on
  hover. When a node is clicked, open a side panel showing the complete wiki
  page. Load the graph library from a CDN so the file works on its own. Run the
  script, open wiki-map.html in my browser, and add a rule to AGENTS.md: rerun
  the script after every ingest.

**What did you observe?**
- Which ideas are most connected to other ideas?
- Does the visual graph reveal relationships that were less obvious when reading individual pages?
