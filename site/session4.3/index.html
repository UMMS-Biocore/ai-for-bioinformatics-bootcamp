Session 4.3 · Hands-on

The agent prepares the run. You launch it.

You drive Foundry Connect from an AI agent in VS Code: set up an RNA-seq run by prompt, check it, and press Run yourself. Then you compare RSEM and Salmon on a real 24-sample run, with the data going straight to disk instead of through the chat, and you check the first plot before you believe it. Last, you count differentially expressed genes for all 28 pairs of groups and check your chart against ours.

Go to the hands-on → VS Code · Claude Code or Codex · Foundry Connect

Foundry in five minutes

Foundry Connect runs pipelines on the UMass HPC cluster from a web page. You pick a pipeline, point it at your files, and it runs the jobs on the cluster under your own account. If you finished the Session 1 pre-work, this is already done; check the last step and move on. That page has screenshots for each step.

Log in once

Open viafoundry.umassmed.edu and sign in.

Make an SSH key

Open the Credentials tab, choose Create Credential, pick SSH, then Generate Keys for Me.

Give the cluster the public key

Copy the public key and paste it at hpcportal.umassmed.edu/PublicKeys/Create.

Set your run environment

Open the Run Environments tab, select that SSH key, press Test Connection, then Save Changes.

Checkpoint Test Connection is green. Without it, the run you prepare below stops at step 5 of its prompt.

Today’s tool: an agent in a folder

Today you work in VS Code, with Claude Code or with Codex. Either one sees the files in one folder, writes and runs scripts there, and saves what it makes next to them. That is what lets it handle files too big to paste into a chat.

It asks before it acts only in the right mode. Set it before you start:

  • Claude Code: keep the default mode, Ask before edits. Do not switch to Edit automatically or any bypass mode today. Each file edit shows as a change to accept or reject, and each command and each Foundry action asks you to allow it or deny it.
  • Codex: use Agent mode, not Agent (full access).

The prompts below also say “do not launch it” in words, so even a wrong mode does not start a job on the cluster.

Connect claude.ai to Foundry

In claude.ai, open Settings, then Connectors, then Add custom connector. Use this URL and sign in to Foundry when asked:

VS Code

Install VS Code

Follow the steps in 2.0 if you do not have it yet.

Add the extensions

Open Extensions in the left bar and install Claude Code for VS Code (Anthropic) or Codex (OpenAI), or both.

Make the RNA-Seq folder and open it

Today’s work goes in Documents/bootcamp/session4/RNA-Seq, next to the notebooks from 4.0. Make it in Terminal (macOS) or PowerShell (Windows):

macOS:

mkdir -p ~/Documents/bootcamp/session4/RNA-Seq

Windows PowerShell:

New-Item -ItemType Directory -Force (Join-Path ([Environment]::GetFolderPath('MyDocuments')) 'bootcamp\session4\RNA-Seq') | Out-Null

Then in VS Code choose File, Open Folder, go to Documents, bootcamp, session4, select RNA-Seq, and open it. From now on the VS Code terminal starts in this folder, and the agent works and saves its files here.

Trust the folder

Accept the trust prompt. If you missed it, open Manage (the gear), then Workspace Trust.

A five-minute tour

The Explorer lists the files in the folder. The editor opens them. Terminal, New Terminal opens a terminal already inside the folder: PowerShell on Windows, the usual Terminal shell on macOS. The Claude or Codex panel is where you type prompts. When the agent proposes an edit you see the change and accept or reject it; when it wants to run a command or call Foundry it asks first.

Check uv and Python

The agent runs its Python scripts with uv, which you set up in 4.0. In the VS Code terminal, on macOS or Windows:

uv run python --version

Checkpoint It prints a Python version, such as Python 3.13.7. If it says uv is not found or not recognized, quit VS Code completely and open it again. Still not found? Do the Install uv and Python step in 4.0, then come back.

If an install fails, fix it with the agent

Errors during installs are normal, and the agent is good at reading them. Select the whole error in the terminal, copy it, and paste it into the agent panel inside this prompt, replacing the two lines in angle brackets:

I ran this command in a terminal on my computer: <paste the command> It failed with this error: <paste the full error> Tell me which operating system and terminal you think I am using, explain in plain words what went wrong, and suggest the smallest fix. Do not run anything until I say yes.
  • Paste the whole error, not just the last line. The cause is often near the top.
  • Before you paste, delete anything that looks like a password or access token.
  • Read the fix before you allow it. If it needs admin rights (sudo on macOS, Run as administrator on Windows), stop and ask an instructor.
  • Still stuck after two tries? Raise your hand. Then try the next step: most of today still works while one install is broken.

Hands-on: launch a run by prompt

The template is run 12301: the RNA-seq pipeline on six small paired-end mouse samples, three control and three experimental. It finishes in minutes. Type each prompt in the agent panel in your RNA-Seq folder.

List your runs

Using Foundry Connect, list my 5 most recent runs with their ID, name, pipeline, status and date.

A brand new account may have none. That is expected.

Duplicate and fill, without launching

Duplicate Foundry run 12301 into a new run named "Bootcamp RNA-seq <your name>". Set it up as below, and do not launch it. 1. Samples: the six paired-end samples in /share/data/umw_biocore/genome_data/mousetest/mm10/gz/ (control_rep1, control_rep2, control_rep3, exper_rep1, exper_rep2, exper_rep3; files are named <sample>.1.gz and <sample>.2.gz). If the duplicate lost its sample input, reuse the dataset from run 12301. 2. Make a metadata file with columns sample_name and group. The control_rep samples are group control; the exper_rep samples are group exper. Save a copy as metadata.tsv in this folder. 3. Make a comparisons file with columns controls, treats, names and one row: control, exper, exper_vs_control. Save a copy as comparisons.tsv in this folder. 4. Attach both to the new run as its groups file and comparison file, and turn on DESeq2 after RSEM. 5. Use my own run environment, not the one copied from 12301. If I do not have one, stop and tell me. 6. Run the preflight check and show me its result.
What did you observe?
  • Which Foundry actions did the agent ask permission for?
  • Open metadata.tsv and comparisons.tsv. Are they what you asked for?

Get the link

Real data: RSEM against Salmon

Run 11724: 24 mouse liver samples, chow or high-fat diet, four genotypes, three replicates each (the homework study). Do replicates agree better with RSEM or with Salmon?

The tables are about 16 MB, too big for the chat, so the agent works on files on disk and shows you a summary.

The analysis

If data/rsem and data/salmon are not in this folder, download https://biocore.umassmed.edu/data/session4/session4_data.zip and unzip it here. Using the gene TPM tables from RSEM and Salmon (samples are <diet>.<genotype>.rep<n>), correlate each pair of replicates within each group. Sum rows by gene name, keep genes with TPM of at least 1 in some sample, use Pearson on log2(TPM+1) and Spearman on TPM. Make box plots by group with RSEM and Salmon side by side. Do not print the data files: write a Python script, run it with uv, and show me a small summary table.

Check before you believe

Redo the plots using only the genes both tools keep. Did the conclusion change, and why?
READ What we got
RSEM looks better at first (median Spearman 0.961 against 0.929), but on shared genes the gap nearly disappears (0.966 against 0.961). Most of the difference was low-count genes that only Salmon keeps.

All-to-all differential expression

How many genes change between each pair of the 8 groups? That is 28 pairs. Compare your result with our reference chart.

The analysis

If data/rsem/genes_expression_expected_count.tsv is not in this folder, download https://biocore.umassmed.edu/data/session4/session4_counts.zip and unzip it here. It holds RSEM expected counts (columns gene, transcript, then 24 samples). With pydeseq2, test every pair of the 8 groups: sum rows by gene name and round, keep genes with at least 10 counts in some sample, design ~group, apeGLM shrinkage. Count genes with padj < 0.05 and shrunken log2 fold change above 1 (up) or below -1 (down). Do not print the data file: write a Python script, run it with uv, and save the counts to de_counts.tsv.

Draw it

From de_counts.tsv, make one self-contained HTML page: a bar per pair centred on zero, down genes in blue to the left, up genes in red to the right, one shared scale, numbers on the bars. Open it in my browser.

Check against ours

Your counts may differ from ours by a few genes: software versions move genes that sit right on a cutoff. For an exact match, run all2all_de.py, the script that made our chart: uv run all2all_de.py data/rsem/genes_expression_expected_count.tsv.

READ What we got
Diet dominates: high-fat against chow changes about 500 to 800 genes, and over 2,000 in ALAB. Genotypes barely differ on chow. On high-fat diet, ALAB stands apart.

Advanced: get the files straight from Foundry

Optional. The same analysis, but the agent fetches the tables from run 11724 itself with the foundry command from the Foundry SDK, which writes straight to disk at any size. This is the route that works on your own runs after the course, when there is no hosted copy. It works the same on macOS and on Windows (PowerShell).

Install the SDK

In the VS Code terminal:

uv tool install https://github.com/UMMS-Biocore/foundry-sdk/archive/refs/heads/main.zip
uv tool update-shell

Close and reopen the terminal, then check:

foundry --version

No Git needed. uv, which you set up in 4.0, keeps the SDK in its own environment and puts foundry on your PATH. On Windows, if a new terminal still says foundry is not recognized, quit VS Code completely and open it again.

Or ask the agent to install it. Only the install: the login in the next step is yours to do.

Install the Foundry SDK with: uv tool install https://github.com/UMMS-Biocore/foundry-sdk/archive/refs/heads/main.zip. Then run uv tool update-shell, and check it with foundry --version. Do not run foundry configure; I will log in myself.

If a step here fails, use the troubleshooting prompt from the VS Code section.

Log the SDK in, yourself

Do this in the terminal, not through the agent:

foundry configure --hostname https://viafoundry.umassmed.edu

When it asks for a method, type 2 (Username and Password) and sign in with your Foundry username, which is your email address, and your password. The password prompt shows nothing as you type. The SDK saves your login in a file named .viaenv in your home folder.

UMass Foundry does not use a second sign-in factor yet. If it is turned on later, the SDK also asks for the 6-digit code from your authenticator app.

Check it works

foundry reports list-processes 11724

Hand it to the agent

Use the foundry command line tool to download rsem_summary/genes_expression_tpm.tsv and salmon_count/genes_expression_tpm.tsv from Foundry run 11724 into data/rsem and data/salmon in this folder. Do not open or print them. Then do the same analysis as before on these files.
Rules
  • Never paste a password or access token into a chat. If an agent asks for one, say no.
  • The SDK reads its own saved login. The agent has no reason to open .viaenv.
  • On a shared computer, delete .viaenv when you are done.
