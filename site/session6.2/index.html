Session 6.2 · Hands-on

Run a Xenium analysis on Foundry. You launch it.

The same pattern as 4.2, on spatial data. An AI agent sets up Foundry’s Xenium Spatial Analysis pipeline on public human lung data, you check every setting and press Run, and about fifteen minutes later you have a report with clusters and niches drawn on the tissue.

Go to the hands-on → VS Code · Claude Code or Codex · Foundry · Playwright

The data

10x Genomics’ public Xenium human lung, 2 fields of view dataset (Xenium_V1_human_Lung_2fov, CC BY 4.0): a piece of a human lung section about 1.2 by 0.75 mm, measured with a 289 gene panel. The output bundle holds 11,898 segmented cells. It is small on purpose, so the run finishes during class.

We put it on the cluster where every account can read it, with the two sheets the pipeline takes:

/share/data/umw_biocore/genome_data/xenium/lung2fov/
  Lung2fov_outs/            the 10x output folder
  Lung2fov_cell_stats.csv   one row per cell: ID, transcripts, cell and nucleus area
  samplesheet.tsv           sample_name, xenium_path
  metadatasheet.tsv         sample_name, cell_stats_path, condition, replicate, tissue

The original download is a 278 MB ZIP from 10x, Xenium_V1_human_Lung_2fov_outs.zip. You do not need it today.

Two things we did to the bundle, and why
  • The pipeline expects a cell_feature_matrix/ folder. Newer 10x bundles ship it only as cell_feature_matrix.tar.gz, so we unpacked it.
  • The pipeline also wants a cell stats file of the kind Xenium Explorer exports. Public data has none, so we built one from cells.csv.gz. Leaving that column blank stops the run.
Fixing a pipeline’s input rather than its code is a normal workaround. Write it down, as here, so the next person knows.

What the pipeline does

Xenium Spatial Analysis Pipeline (version 1.0.4 on Foundry; version 1.0.3 gives the same results) runs two steps: it prepares the 10x folder, then renders one R Markdown report with Seurat.

  1. Load. Read the cell by gene counts, cell centroids, and control probe counts.
  2. QC. Drop cells with no transcripts, then keep cells between the 1st and 99th percentiles of transcripts per cell and of genes per cell.
  3. Normalize and reduce. SCTransform, then PCA, with the number of PCs picked from the PCA.
  4. Cluster. Cluster at 20 resolutions from 0.1 to 2.0 and pick one by how stable the clusters stay across resolutions.
  5. Niches. Group cells into 4 niches by the clusters of their 20 nearest neighbors, as in 6.1.
  6. Markers. Find marker genes for every cluster.

It writes two files: an HTML report and the Seurat object as an .rds file. You open both in 6.3.

Before you start

Foundry, the agent, and Playwright from 4.2

You need what you set up in Session 4.2: a Foundry run environment whose Test Connection is green, an agent in VS Code with Foundry Connect, and the Playwright browser. Keep the agent in ask-first mode, as described in 4.2.

Make the folder and open it

macOS:

mkdir -p ~/Documents/bootcamp/session6/xenium

Windows PowerShell:

New-Item -ItemType Directory -Force (Join-Path ([Environment]::GetFolderPath('MyDocuments')) 'bootcamp\session6\xenium') | Out-Null

Then in VS Code choose File, Open Folder, and open Documents, bootcamp, session6, xenium. The agent saves its notes and screenshots here.

Hands-on: set up the run

1. Set it up by prompt

Using the Playwright browser, open https://viafoundry.umassmed.edu and stop there so I can sign in myself. When I say I am signed in, do the following in that browser. 1. Create a new run of the pipeline named "Xenium Spatial Analysis Pipeline", in a project named bootcamp_test. Create the project if it does not exist. Name the run "Xenium lung 2FOV". 2. Choose my own run environment on hpc.umassmed.edu (named UMASS SCI Cluster). If you see more than one, ask me which. 3. Stop and ask me which Execution Directory to use. Do not choose one yourself. Enter exactly the folder I give you. Foundry will not accept the input files until this is set. 4. Set the samplesheet input to the file /share/data/umw_biocore/genome_data/xenium/lung2fov/samplesheet.tsv and the metadatasheet input to /share/data/umw_biocore/genome_data/xenium/lung2fov/metadatasheet.tsv. These are files already on the cluster; do not upload anything. 5. Leave the pipeline's own settings at their defaults. 6. Under Advanced options, make sure Singularity is on, and set the image to quay.io/ayush_praveen/ubuntu-seurat:5.3.0 (replace any image already filled in) and the run options to -B /home:/home -B /share:/share -B /pi:/pi. Turn on the executor settings for all processes with queue short, memory 32 GB, 4 CPUs, and time 240 minutes. Leave the per-process executor settings as Foundry filled them. 7. Save the run, but do not press Run. Give me a clickable link to the run, save a screenshot of the run page as run_setup.png in this folder, and show me a table of everything you set.

Sign in by hand when the browser opens. If the agent asks for your password, say no. For the Execution Directory, give it a folder you can write to on the cluster, such as /home/<your cluster username>/bootcamp/xenium.

2. You check, you launch

Open the link and check: pipeline Xenium Spatial Analysis Pipeline, the two sheet paths exactly as above, your own run environment, Singularity on with the Seurat 5.3.0 image, and the Execution Directory you gave. Then press Run.

The rule The agent prepared the run. You launch it.

What did you observe?
  • Did the agent stop for you three times: to sign in, for the Execution Directory, and before Run?
  • Does run_setup.png agree with its table?
  • The container image was the one setting we had to spell out. What would a run with the image Foundry filled in have tried to do?

3. Watch it run

The cluster jobs take a few minutes; with queueing, expect about fifteen. Ask the agent to report instead of refreshing the page:

Using Foundry Connect, tell me the status of my run "Xenium lung 2FOV" in project bootcamp_test. If it is still running, say which step it is on. If it failed, show me the last 30 lines of its log and explain the error in plain words. Do not change or relaunch anything.

Checkpoint The run ends as Completed, and its Reports tab shows HTML_Report/Lung2fov.analysis_report.html (about 5 MB). The Seurat object is written next to it on the cluster, not shown in Foundry: <your Execution Directory>/report<run id>/Analysis_Results_RDS/Lung2fov.analysis.rds (about 40 MB).

While it runs

Use the wait to question the agent about what you just launched. Make it say which parts it knows from a source and which it is inferring.

I launched a Xenium analysis on 10x's public human lung 2 field of view dataset, measured with a 289 gene panel. Explain what files a Xenium output folder contains and which ones a cell by gene analysis needs. Then explain what a negative control probe and a blank codeword are, and what rate of them would make me distrust a run.
The pipeline keeps cells between the 1st and 99th percentiles of transcripts and genes per cell. With a 289 gene panel, what kinds of cells could that remove for the wrong reason? Would you set the thresholds differently for spatial data than for single-cell?
The pipeline builds 4 niches from each cell's 20 nearest neighbors. What does a niche capture that a cluster does not, and what would change if I asked for 8 niches instead?

If the run fails

We hit each of these while preparing the session. Ask the agent to read the log with the prompt in step 3, then compare.

  • Rscript: command not found: Singularity is off, or the image is not the Seurat one (Foundry fills in a Space Ranger image that has no R), so the job looked for R where there is none. Fix both as in step 1.6.
  • Image pull fails, or a read-only file system error: the container could not be downloaded into the Singularity cache your run environment uses. Tell an instructor.
  • Argument of `file` function cannot be empty: a sheet path is wrong or blank. Check both paths character by character.

If your run cannot finish in class, nothing is lost: 6.3 uses course copies of the same two output files, from our own run of this setup.
