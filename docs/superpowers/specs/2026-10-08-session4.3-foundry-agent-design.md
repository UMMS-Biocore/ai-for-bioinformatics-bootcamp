# Session 4.3: Run RNA-seq on Foundry with an AI agent

Design spec, 2026-10-08. Taught Fri Oct 9, 2026, as the closing hands-on part of
Session 4, after Manuel Garber's 4.1 talk.

## Goal

Participants leave able to drive Foundry Connect from an AI agent in VS Code:
prepare and launch an RNA-seq run by prompt, then analyze a real run's outputs
with Python, without the data ever passing through the chat. Two course
threads carry through: the agent prepares and the human launches, and the
first plot the agent makes is checked before it is believed.

## Page sections, in teaching order

### A. Foundry in five minutes

What Foundry Connect is (one paragraph: pipelines on the UMass HPC cluster
through a web page). Then numbered steps, condensed from session1.0 and
linking back to it for screenshots:

1. Log in once at `viafoundry.umassmed.edu` (VPN when off campus).
2. Credentials tab, Create Credential, SSH, Generate Keys for Me.
3. Paste the public key at `hpcportal.umassmed.edu/PublicKeys/Create`.
4. Run Environments tab: select that SSH key, Test Connection, Save Changes.

Checkpoint: Test Connection is green. Without it, E2 stops at its step 5.

### B. Today's tool: an agent in a folder

VS Code with Claude Code, or with Codex. A short box on why: it sees the files
in one folder, writes and runs scripts, and saves outputs there. No comparison
table of other apps.

It asks before acting only in the right mode, so the page names it:

- **Claude Code:** keep the default mode, "Ask before edits". Do not switch
  to "Edit automatically" or any bypass mode today. Each file edit shows as a
  diff to accept or reject; each command and each Foundry action shows a
  permission prompt to allow once or deny.
- **Codex:** use "Agent" mode, not "Agent (full access)".

The prompts in E also say "do not launch it" in words, so a wrong mode still
does not start an HPC job. Exact mode names are re-checked in the dry run.

### E. Hands-on: launch a run by prompt

Template run **12301** (RNA-seq Pipeline 1405 v2.7.4, `mousetest_mm10`,
6 paired samples, 10k to 25k reads each, finishes in minutes). Each prompt is
in a copy box.

**E1. List runs**

> Using Foundry Connect, list my 5 most recent runs with their ID, name,
> pipeline, status and date.

A brand new account may have none. That is expected.

**E2. Duplicate and fill**

> Duplicate Foundry run 12301 into a new run named "Bootcamp RNA-seq
> <your name>". Set it up as below, and do not launch it.
>
> 1. Samples: the six paired-end samples in
>    /share/data/umw_biocore/genome_data/mousetest/mm10/gz/ (control_rep1,
>    control_rep2, control_rep3, exper_rep1, exper_rep2, exper_rep3; files are
>    named <sample>.1.gz and <sample>.2.gz). If the duplicate lost its sample
>    input, reuse the dataset from run 12301.
> 2. Make a metadata file with columns sample_name and group. The control_rep
>    samples are group control; the exper_rep samples are group exper. Save a
>    copy as metadata.tsv in this folder.
> 3. Make a comparisons file with columns controls, treats, names and one row:
>    control, exper, exper_vs_control. Save a copy as comparisons.tsv in this
>    folder.
> 4. Attach both to the new run as its groups file and comparison file, and
>    turn on DESeq2 after RSEM.
> 5. Use my own run environment, not the one copied from 12301. If I do not
>    have one, stop and tell me.
> 6. Run the preflight check and show me its result.

**E3. Link**

> Give me a clickable link to the new run, in the form
> https://viafoundry.umassmed.edu/runs/<run ID>.

**E4. You check, you launch**

Open the link and check: 6 samples, groups control and exper, comparison
exper_vs_control, your own run environment. Then press Run. The agent
prepared it; the person launches it.

### F. Real data: RSEM vs Salmon

Run **11724**: 24 mouse liver samples, chow or high-fat diet crossed with
four genotypes (wt, ALAB, J1c, J2c), 3 replicates each, from Vernia et al.
2014. Its RSEM and Salmon gene TPM tables (about 16 MB each) are too large for
the connector, which drops the connection above a few MB. The page says so in
one short box, with the rule: small files through the chat, big files
straight to disk.

Hosted copies (route chosen 2026-10-08):

- `site/data/session4/rsem_genes_expression_tpm.tsv`
  (from 11724 `rsem_summary/genes_expression_tpm.tsv`)
- `site/data/session4/salmon_genes_expression_tpm.tsv`
  (from 11724 `salmon_count/genes_expression_tpm.tsv`)

Columns: `gene`, `transcript`, then 24 samples named `<diet>.<genotype>.rep<n>`.

**F1. The analysis**

> Download these two files into a data folder here:
> https://biocore.umassmed.edu/data/session4/rsem_genes_expression_tpm.tsv
> https://biocore.umassmed.edu/data/session4/salmon_genes_expression_tpm.tsv
> They are gene TPM tables from Foundry run 11724 quantified with RSEM and
> with Salmon. Sample names are <diet>.<genotype>.rep<n>; the group is the
> name without .rep<n>.
>
> I want to compare Spearman and Pearson correlations inside each group. In
> each group, correlate every pair of different replicates once: rep1 with
> rep2, rep1 with rep3, rep2 with rep3. No sample with itself, no pair twice.
> Do this for RSEM and for Salmon. Drop the transcript column and add up rows
> that share a gene name. Keep genes with TPM of at least 1 in some sample.
> Use log2(TPM+1) for Pearson and TPM for Spearman. Make two box plots, one for Pearson and
> one for Spearman, with the groups on the x axis and RSEM and Salmon side by
> side in each group, and show the individual points.
>
> Do not open or print the data files. Write a Python script in this folder
> that does the work, run it with uv, save the plots and a small table here,
> and show me only that table: for each tool and each correlation, the number
> of genes kept, the number of pairs, and the median and minimum over all
> pairs. Before plotting, check that there are 24 samples, 8 groups and 3
> pairs per group, and stop if not.

**F2. Check before you believe**

> RSEM and Salmon kept different numbers of genes. Redo both plots using only
> the genes that pass the filter in both. Match the two tables by gene name,
> with the same genes and the same sample columns in the same order, and tell
> me how many genes are shared. Did the conclusion change, and why?

Reading guide on the page. **Summary statistic, defined:** per tool and per
correlation, the median over all 24 within-group pairs (8 groups × 3 unique
pairs), not a median of group medians. The Oct 5 analysis gave, with each
tool's own gene set, RSEM higher in all 8 groups (median Spearman 0.961 vs
0.929), and on the 16,201 shared genes a much smaller gap (0.966 vs 0.961).
Those numbers are provisional: the build regenerates them from the hosted
files (build step 2) and the page quotes the regenerated values. The message
stays qualitative: most of the first difference came from low-count genes
Salmon keeps. Each box holds only 3 points, so the plots show spread, not a
test.

### G. Advanced: get the files straight from Foundry with the SDK

Optional, marked "Advanced" on the page, after F. The same analysis as F, but
the agent fetches the tables from run 11724 itself with the ViaFoundry SDK's
`foundry` command, which writes straight to disk at any size. This is the
route that works on your own runs after the course, when there is no hosted
copy.

Works the same on Mac and Windows (PowerShell): no Git, no shell tricks.

1. **Install the SDK** in the VS Code terminal:

   ```
   uv tool install https://github.com/UMMS-Biocore/foundry-sdk/archive/refs/heads/main.zip
   uv tool update-shell
   ```

   Close and reopen the terminal, then check with `foundry --version`
   (1.1.0 as of 2026-10-08). The zip URL means Git is not needed; uv is
   already installed from 4.0, and `uv tool` keeps the SDK in its own
   environment and puts `foundry` on PATH.
2. **Log the SDK in, yourself, in the terminal.** Not through the agent.

   ```
   foundry configure --hostname https://viafoundry.umassmed.edu
   ```

   When it asks for a method, type **2** (Username and Password) and sign in
   with your Foundry username and password. The password prompt is hidden.
   UMass Foundry does not use multi-factor sign-in yet, so that is all it
   asks. The SDK supports both: on an instance with multi-factor sign-in
   turned on, it then also asks for the 6 digit code from your authenticator
   app. (Small note on the page, so the steps stay right if UMass turns it
   on.)
   The SDK saves your login in `.viaenv` in your home folder. Nothing secret
   goes on the command line, into shell history, or into the chat. The page
   gives only this route; option 1 is not mentioned.
3. **Check it works:** `foundry reports list-processes 11724`.
4. **Prompt the agent:**

   > Use the foundry command line tool to download
   > rsem_summary/genes_expression_tpm.tsv and
   > salmon_count/genes_expression_tpm.tsv from Foundry run 11724 into
   > data/rsem and data/salmon in this folder. Do not open or print them.
   > Then do the same analysis as before on these files.

Rules box on the page: never type a password or token into a chat; if an
agent asks for one, say no; the SDK reads its own saved login, and the agent
has no reason to open `.viaenv`. On a shared computer, delete `.viaenv` when
done.
